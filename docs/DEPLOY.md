# Деплой на Vercel

Состояние на 2026-08-13. Проверено на собранном приложении (`npm run build`
+ `next start`), а не по документации.

---

## Что даёт деплой прямо сейчас

Сайт поднимется и будет работать: вход, навигация, разводные страницы всех
десяти брендов, сам редактор. **Но содержимого не будет и сохранять не
получится** — CMS в этот момент ещё не подключена.

Проверено запросами к собранному приложению без переменных Strapi:

| действие | ответ |
| --- | --- |
| вход админом | 200 |
| экран редактора открывается | 200 |
| Save draft / Publish | 503 «CMS не подключена…» |
| правка рубрик, уведомление | 503, то же сообщение |
| медиатека | 503, список пуст |

Навигация при этом берётся из кода (`sidebarDirectory`), поэтому сайдбар не
пустой: у Birbank настоящий состав разделов, у остальных девяти —
плейсхолдер из четырёх пунктов (см. OPEN_QUESTIONS №13).

## Шаг 1. Переменные окружения на Vercel

**Обязательны три.** Без них сайт собирается, но пользоваться им нельзя —
проверено:

| переменная | если не задать |
| --- | --- |
| `SESSION_SECRET` | верный пароль → **500** (`SESSION_SECRET is not set`) |
| `VIEWER_PASSWORD_HASH` | вход отдаёт **401 всем**: совпасть не с чем |
| `ADMIN_PASSWORD_HASH` | в редактор не попасть |

Хэши — bcrypt. Сгенерировать:

```bash
node -e "console.log(require('bcryptjs').hashSync('пароль-сюда', 12))"
```

Секрет сессии — не меньше 32 символов:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

Значения вносятся **в интерфейсе Vercel** (Project → Settings → Environment
Variables), а не в репозиторий: `.env.*` в `.gitignore`, и это нарочно.

### Когда появится CMS

| переменная | зачем |
| --- | --- |
| `STRAPI_API_URL` | `https://<домен-strapi>/api` |
| `STRAPI_API_TOKEN` | read-only, им сайт читает контент |
| `STRAPI_WRITE_TOKEN` | только для сохранения из редактора |

Разделение токенов не формальность: читающий раздаётся шире, и его утечка не
должна давать право менять контент.

`STRAPI_API_URL` автоматически попадает в CSP (`img-src`/`media-src`) и в
`images.remotePatterns` — см. `next.config.mjs`. Без этого прод заблокировал бы
картинки из CMS.

## Шаг 2. Настройки проекта

Ничего специально задавать не нужно, но стоит проверить:

- **Framework Preset** — Next.js, определяется сам;
- **Node.js Version** — 22.x, зафиксирована в `package.json` → `engines`;
- **Install Command** — обычный `npm install`. Флаг `legacy-peer-deps` лежит
  в `.npmrc` в репозитории; когда-то он передавался руками только локально, и
  из-за этого CI падал с `ERESOLVE`, а локально всё ставилось;
- **Root Directory** — корень репозитория. `cms/` в сборку не уезжает, см.
  `.vercelignore`.

`strapi-schemas/` в `.vercelignore` исключать **нельзя**: `lib/strapi/populate.ts`
импортирует схемы компонентов прямо в сборку.

## Шаг 3. Что сломается именно на Vercel

Эти вещи работают на одном сервере и перестают работать в бессерверной среде.
Записаны здесь, чтобы не выяснять их по инциденту.

### Ограничитель попыток входа станет декоративным

`lib/auth/loginAttempts.ts` держит счётчик в памяти процесса. Vercel поднимает
много независимых функций — у каждой свой счёт, и предел «10 попыток на адрес»
превращается в «10 × число экземпляров». Защита от подбора фактически исчезает.

Лечится внешним хранилищем (Upstash Redis) или ограничением на стороне самого
Vercel. До тех пор единственная реальная защита — длина пароля.

### Медиа-прокси упирается в лимиты функции

`/api/media/file/[id]` стримит файл через серверный роут: таймаут 10 с на Hobby,
60 с на Pro, и трафик идёт мимо CDN. Крупные PDF могут не успевать.

### Трафик на видеофоне

`public/images/login-background.mp4` — 11,8 МБ, грузится **до** входа, то есть
у любого, кто открыл адрес. Картинка-подложка показывается сразу, так что экран
не пустует, но трафик расходуется. Уменьшить:

```bash
ffmpeg -i login-background.mp4 -vf scale=1280:-2 -c:v libx264 -crf 28 \
  -preset slow -an -movflags +faststart out.mp4
```

Ещё примерно треть снимет второй `<source>` в webm.

## Шаг 4. Чтобы заработал редактор

Редактор ничего не хранит сам: он сериализует холст и отдаёт серверному роуту,
а тот пишет в Strapi. Пока Strapi живёт в Docker на машине разработчика,
Vercel до неё не достучится ни при каких переменных.

Нужно всё перечисленное, по порядку:

1. **Strapi по публичному HTTPS-адресу.**
2. **Управляемый PostgreSQL** рядом — не в том же контейнере, иначе база живёт
   до первого перезапуска.
3. **Приватный S3-бакет** для загрузок. Без него файлы лежат внутри контейнера
   и исчезают при перезапуске вместе со всей медиатекой (№97). Публичное чтение
   в бакете должно быть запрещено — иначе прокси сайта обходится прямой
   ссылкой (№112).
4. **Схемы контент-типов перенесены** — порядок в `strapi-schemas/README.md`.
5. **Два токена**, выпущенных в этом Strapi.
6. **Переменные `STRAPI_*` на Vercel.**

### Грабли, на которые уже наступали

- **`API_TOKEN_SALT` нельзя менять между запусками.** Стоит подменить — и все
  выпущенные токены разом перестают приниматься, сайт отвечает 401 (№96).
- **Локальный контент не переедет сам**: он в локальной базе. Либо дампом,
  либо заводить заново.
- **Админка Strapi окажется в интернете.** Vercel не ходит в закрытую сеть,
  значит вход в саму CMS становится рубежом обороны.

## Проверка после деплоя

```bash
# без входа: всё уводит на логин, кроме самого логина и его ассетов
curl -s -o /dev/null -w "%{http_code}\n" https://<домен>/guidelines/retail   # 307
curl -s -o /dev/null -w "%{http_code}\n" https://<домен>/login               # 200

# заголовки безопасности на месте
curl -sI https://<домен>/login | grep -iE "content-security-policy|x-frame|nosniff"
```

Дальше — войти, убедиться, что сайдбар показывает десять брендов, и открыть
редактор: он должен открыться, а «Publish» — сказать про неподключённую CMS
словами, а не кодом.
